# MTMbot — بوت تداول Multi-Timeframe Momentum

بوت تداول مكتوب بلغة Python بمعمارية واحدة تُستخدم في **الباك-تست** و**التداول الورقي** و**التداول الحقيقي**.
الهدف الأساسي ليس "وعود أرباح" بل **صفر أخطاء منطقية**: لا نظرة إلى المستقبل (look-ahead)، رسوم وانزلاق
محسوبان على كل تنفيذ، حدود مخاطر صارمة، حالة محفوظة تنجو من إعادة التشغيل، واختبارات تغطي كل ذلك.

> ⚠️ **تنبيه**: هذا ليس نصيحة مالية. النتائج التاريخية لا تضمن المستقبل. جرّب دائماً على حساب ورقي
> أو testnet قبل أي مال حقيقي.

## البدء السريع

```bash
python -m venv .venv && source .venv/bin/activate
pip install -e ".[dev]"          # للتداول الحقيقي: pip install -e ".[live]"

# 1) التحقق من الإعدادات
cp config.example.toml config.toml
python -m mtmbot validate --config config.toml

# 2) تنزيل بيانات مجانية (بدون مفاتيح API) — أي إطار زمني
python -m mtmbot download --symbol BTC/USD --timeframe 1h \
  --start 2024-01-01 --end 2026-11-01 --out data/BTC-USD_1h.csv

# 3) باك-تست + تقرير HTML/JSON في reports/
python -m mtmbot backtest --data data/BTC-USD_1h.csv

# 4) تحقق خارج العينة (الأرقام الوحيدة التي تُعتبر دليلاً)
python -m mtmbot walkforward --data data/BTC-USD_1h.csv --folds 4 --objective sharpe
python -m mtmbot walkforward --data data/BTC-USD_1h.csv --grid grid.example.toml

# 5) تداول ورقي على بيانات السوق الحقيقية
python -m mtmbot paper --config config.toml --state state/paper.json

# 6) التداول الحقيقي (يتطلب موافقة صريحة + مفاتيح في البيئة)
export MTMBOT_LIVE_OK=1 MTMBOT_API_KEY=... MTMBOT_API_SECRET=...
python -m mtmbot live --config config.toml --confirm-live --state state/live.json
```

`download` يبني أي إطار زمني تطلبه (مثل `4h`) من أدق تفصيل متاح في Coinbase ويعيد تجميعه تلقائياً.

## كيف تعمل الاستراتيجية؟

1. **اتجاه الإطار الأعلى (HTF):** إطار أعلى بـ `htf_factor` (افتراضياً 1h → 4h). شرط الشراء:
   `EMA(fast) > EMA(slow)` والسعر فوق `EMA(slow)`. البيع بالعكس.
2. **الزخم على الإطار الأساسي:** لا دخول إلا إذا تقاطع السعر فوق `EMA(21)` مع `RSI ≥ 52`
   (أو تحت `EMA` مع `RSI ≤ 48` للبيع). الدخول عند **افتتاح الشمعة التالية**.
3. **الوقف والهدف:** الوقف = `2 × ATR`، الهدف = `2R`.
4. **الإدارة:** عند `+1R` ينتقل الوقف إلى نقطة الدخول، وعند `+2R` يبدأ التتبّع `2 × ATR`.
   الوقف **لا يتسع أبداً** — فقط يضيق.
5. **الخروج:** وقف/هدف أو انقلاب اتجاه الإطار الأعلى.

قواعد مقاومة النظرة للمستقبل:
- إشارة الشمعة `i` تُنفَّذ على افتتاح `i+1` حصراً.
- شمعة الإطار الأعلى لا تُقرأ إلا بعد إغلاقها فعلياً (`map_htf_indices`).
- إذا لمس الشريط الوقف والهدف معاً، يُفترض **الوقف** (أسوأ حالة).

## التحقق خارج العينة (Walk-forward)

تحسين المعاملات على كل البيانات يُنتج أرقاماً جميلة وكاذبة. الأمر `walkforward` يفعل العكس:

1. يقسّم التاريخ إلى نوافذ اختبار متتالية غير متداخلة.
2. لكل نافذة يختار المعاملات من **بيانات ما قبلها فقط** (نافذة تدريب متدحرجة).
3. ينفّذ تلك المعاملات على النافذة التالية، وينقل رأس المال من نافذة إلى التي بعدها.
4. يقارن داخل العينة (تدريب) وخارج العينة (اختبار) ويعرض الانحدار بينهما بدل إخفائه.

طول نافذة الاختبار يُحسب من أبطأ تركيبة في الشبكة (أطول warm-up)، فما تُختبر تركيبة على بيانات
أقل من احتياجها. ولا تدخل أي شمعة من نافذة الاختبار في اختيار معاملاتها — وهذا مُختبَر آلياً
(اختبار يعدّل بيانات الاختبار فقط ويتحقق أن الاختيار لم يتغير).

### نتيجة حقيقية (BTC/USD 1h، 24,831 شمعة، 4 نوافذ، 16 تركيبة، objective=sharpe)

| النافذة | فترة التدريب | فترة الاختبار | المعاملات المختارة | داخل العينة | خارج العينة |
|---|---|---|---|---|---|
| 1 | 2024-01-01..2025-09-12 | 2025-09-12..2025-12-25 | stop=2.5 fast=13 rr=3.0 slow=89 | −4.62% | −8.45% |
| 2 | 2024-04-13..2025-12-25 | 2025-12-25..2026-04-07 | stop=2.5 fast=13 rr=2.0 slow=89 | −12.59% | +1.89% |
| 3 | 2024-07-25..2026-04-07 | 2026-04-07..2026-07-20 | stop=2.5 fast=13 rr=3.0 slow=55 | −8.80% | −0.72% |
| 4 | 2024-11-06..2026-07-20 | 2026-07-20..2026-10-31 | stop=2.5 fast=13 rr=3.0 slow=55 | −8.71% | −9.82% |

| الإجمالي خارج العينة | القيمة |
|---|---|
| العائد | **−16.48%** |
| أقصى سحب | −18.17% |
| Sharpe | −2.05 |
| الصفقات | 138 (فوز 23.2%، توقّع −0.25R) |
| متوسط داخل العينة | −8.68% (وسيط −8.75%) |
| الكفاءة OOS / IS | +1.90 |
| ثبات المعاملات | 50% من النوافذ اختارت نفس المعاملات |

**القراءة الصادقة:** البحث لم يجد أي تركيبة رابحة حتى داخل العينة، وخارج العينة أسوأ. الاستنتاج
العملي: **لا تتداول هذه العائلة من المعاملات على BTC/USD 1h بالرسوم الحالية.** هذا هو الغرض من
الأداة: أن تكتشف ذلك قبل خسارة المال لا بعدها.

**تنبيه على تفسير الكفاءة:** النسبة موجبة (+1.90) لأن البسط والمقام سالبان. معناها أن الخسارة خارج
العينة تعادل 1.9× متوسط خسارة التدريب — أي تدهور، وليست إشارة إيجابية. لا تنظر إلى هذه النسبة
منفصلة عن إشارة العائد.

## قواعد إدارة المخاطر

| القاعدة | الافتراضي |
|---|---|
| مخاطرة لكل صفقة (من الدخول للوقف) | 0.5% من حقوق الملكية |
| حد المركز الواحد | 100% من حقوق الملكية notional |
| حد الخسارة اليومي | 3% (يُلغى مع يوم جديد) |
| قاطع السحب الأقصى | 20% (يُقفل حتى إعادة تعيين يدوية) |
| أقصى مسافة وقف | 10% |
| مركز واحد لكل رمز | نعم |

حجم المركز = `(equity × 0.5%) ÷ |الدخول − الوقف|`، ثم يُقيَّد بحد المركز ويُقرَّب لأسفل.
لا تُفتح صفقة إذا كان حجمها أقل من `min_notional` أو إذا كان الوقف في الاتجاه الخاطئ.

## ضمانات "صفر أخطاء"

- **165 اختباراً** تغطي المؤشرات، إعادة التجميع، منع look-ahead، الرياضيات المالية، حدود المخاطر،
  الحالة، الواجهة، التقارير، وWalk-forward (بما فيها اختبار تسرّب البيانات).
- **`ruff` نظيف** و**`mypy` نظيف** على 26 ملفاً (انظر `pyproject.toml`).
- **حتمية:** نفس البيانات + نفس الإعدادات = نفس النتيجة بالضبط (مُختبر).
- **الرسوم والانزلاق** على كل تنفيذ، وتُخصم من النقد مرة واحدة فقط.
- **الحالة:** كتابة ذرّية مع `fsync`؛ ملف تالف أو لرمز مختلف = توقف، لا تداول أعمى.
- **إعادة التشغيل:** لا تُعالج الشمعة نفسها مرتين ولا تُفتح صفقة مكررة.
- **حدود الإدخال:** رمز/إطار/نسب/مفاتيح TOML غير المعروفة تُرفض برسالة واضحة.

تشغيل الفحوصات:

```bash
ruff check . && mypy && pytest
```

## نتيجة باك-تست حقيقية (شفافية كاملة)

BTC/USD، إطار 1h، البيانات من Coinbase، 2024-01-01 → 2026-11-01، رأس مال 10,000،
رسوم 10bps وانزلاق 5bps لكل تنفيذ، بالإعدادات الافتراضية:

| المقياس | القيمة |
|---|---|
| الشموع | 24,831 (6,209 شمعة إطار أعلى) |
| صافي العائد | **−16.53%** (شراء واحتفاظ: +83.34%) |
| CAGR | −6.17% |
| أقصى سحب | −20.12% |
| Sharpe / Sortino | −0.96 / −1.36 |
| الصفقات | 253 (نسبة فوز 32.4%، profit factor 0.80) |
| التوقّع | −0.13R |
| الرسوم المدفوعة | 1,887.87 |
| نسبة التعرّض للسوق | 19.2% |

**القراءة الصادقة:** الإعدادات الافتراضية خاسرة على هذه الفترة بعد الرسوم. هذا طبيعي ومتوقّع:
البوت ليس "آلة ربح"، هو **إطار اختبار** يمنعك من خسارة المال في استراتيجية فاشلة. العائد الحقيقي
يأتي من ضبط المعاملات والتحقق خارج العينة (walk-forward)، وليس من تشغيل القيم الافتراضية.

ملاحظة: قاطع السحب (20%) اشتغل وأوقف الدخول الجديد بعد تجاوز الحد، ولهذا ظل البوت خاملاً لبقية
الفترة — وهذا سلوك الحماية المقصود.

## التداول الحقيقي

1. ابدأ بـ **testnet** (`sandbox = true` في `[exchange]`).
2. ضع المفاتيح في البيئة فقط (`MTMBOT_API_KEY` / `MTMBOT_API_SECRET`) — لا تُكتب في الملفات.
3. `MTMBOT_LIVE_OK=1` مطلوب، وبدونه يرفض `CcxtBroker` العمل.
4. **مهم:** في الوضع الحقيقي تُدار الوقفات على إغلاق الشموع. ضع وقفاً أصلياً (native stop)
   على المنصة لكل مركز حقيقي؛ لا تعتمد على البوت وحده بين الشموع.
5. جرّب `paper` أسبوعين على الأقل وراقب السجلات قبل أي مال.

## القيود المعروفة

- مركز واحد لكل رمز، وكل نسخة تتداول رمزاً واحداً (شغّل عدة نسخ لأزواج متعددة).
- لا تنفيذ جزئي ولا هرمية مراكز (pyramiding).
- في الوضع الحقيقي الوقف يُدار على إغلاق الشمعة (انظر التحذير أعلاه).
- محوّل `ccxt` غير مغطى بالاختبارات الآلية لأنه يحتاج مفاتيح منصة؛ اختبره على testnet.
- الحد الأقصى للسحب قد يُتجاوز قليلاً داخل الشمعة قبل أن يُرصد عند الإغلاق (لاحظ 20.12% مقابل 20%).
- القيم الافتراضية ليست مُحسَّنة، وWalk-forward أظهر أنها خاسرة على BTC/USD 1h.
- شبكة Walk-forward الافتراضية (16 تركيبة × 4 نوافذ) تستغرق نحو دقيقتين على 25 ألف شمعة.

## English summary

MTMbot is a correctness-first crypto trading bot: one code path for backtest, paper and live
trading, strict risk limits, atomic state, causal indicators, next-bar execution, fees and
slippage on every fill, walk-forward validation, HTML/JSON reports, and a 165-test suite with
clean `ruff` and `mypy`.

The default parameters are **not** profitable on BTC/USD 1h (2024–2026): −16.5% net vs +83%
buy & hold, 253 trades, profit factor 0.80. Walk-forward confirms it out of sample: −16.48%
over four chained test windows, Sharpe −2.05, 138 trades. That is reported on purpose: the
framework exists to reject bad strategies before they cost money, and to validate good ones
out of sample.

```bash
pip install -e ".[dev]"
python -m mtmbot download --symbol BTC/USD --timeframe 1h --start 2024-01-01 --out data/btc.csv
python -m mtmbot backtest --data data/btc.csv
ruff check . && mypy && pytest
```

Not financial advice. Past performance does not guarantee future results.
